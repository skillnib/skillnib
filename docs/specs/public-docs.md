# Spec: public documentation for the open-source package (README, install, usage, examples, agent prompt)

Status: APPROVED by user 2026-10-12. Slice 10 of the open-source release.
Spec-ID: public-docs
Scope: README.md, docs/guide/**, apps/cli/tests/docs.test.js, package.json, tools/release/lib.mjs

## Purpose

Let a stranger who finds the package understand what SkillTap does, install it, wire it into Claude Code, import their own skills and see a first answer, using only the README and the guide shipped with the package. The text must be true: every command it shows is a real command, every example output is produced by the real CLI, and nothing it says about savings or quality goes beyond what has been measured.

## Non-goals

No new behaviour in the CLI, no website, no logo or badges, no translation, no changelog, no hosted-catalog documentation, no claim about token or dollar savings (those wait for the C3 result and arrive in a later docs change), no documentation of other agents than Claude Code, no Windows instructions beyond saying it is untested.

## Content

`README.md` is the front page: what it is in two sentences, what problem it solves, how it works in one short diagram of the flow (import, compile, ask, deliver), requirements, install, a five-minute quickstart, the two Claude Code modes, command reference, safety, status and limits, licence. `docs/guide/` holds the longer pages that the README links to: `claude-code.md` (hook mode and pull mode, what `tap init claude` changes and how to undo it), `agent-prompt.md` (the text an agent is given in pull mode, how to paste it into another agent's instructions, and how to write asks that retrieve well), `importing.md` (files, directories, GitHub with and without a commit, namespaces, updating, removing), and `examples.md` (worked examples with real output). Pages ship in the package; the `files` list gains `docs/guide`.

## Requirements

- R1 Structure: `README.md` contains, in this order, the headings What it is, Install, Quickstart, Claude Code, Commands, Safety, Status and limits, Licence; it links to each page in `docs/guide/`; and every relative link in the README and the guide resolves to a file that is in the packed tarball.
- R2 Real commands: every `tap` command line in a fenced `sh` block in the README and the guide parses with the CLI's own argument parser to a known command with only known flags, and none uses a flag the usage text does not list.
- R3 Real output: every fenced block marked as example output is reproduced exactly (after path normalisation) by running its command against the fixture skills in a temporary project; the examples are regenerated by a script, never typed by hand.
- R4 One agent prompt: the pull-mode prompt in `docs/guide/agent-prompt.md` is byte-identical to the text `tap init claude --mode pull` writes into `.claude/rules/skilltap.md` (with the command name shown as `tap`), so the guide cannot drift from the product.
- R5 Install steps are checked: the install section names the Node version from `engines`, the package name from `package.json` and `tap --version` as the verification step, and a test fails if any of the three disagree with `package.json`.
- R6 No unmeasured claims: the README and the guide contain no percentage, token count or dollar figure about savings or task success, no word "faster" or "cheaper" applied to SkillTap, and state that the end-to-end measurement (C3) is pending; the one allowed measured statement is the C2 result quoted with its limits, linked to the research record.
- R7 Safety text: the README says that third-party skills are untrusted instructions, that updates are explicit and show a diff first, that `tap init claude` edits only the files listed in the guide and `--undo` restores them, and that the hook never blocks a prompt.
- R8 Package: the packed tarball includes `README.md` and `docs/guide/*.md` and nothing else new; `npm run release:check` passes with the updated `files` list; no code under `apps/cli/src` or `packages/*/src` changes.

## Examples (single happy path and single failure, not a test plan)

- Happy path: a reader runs the three quickstart commands from the README in an empty project (`tap init claude ./skills --mode pull`, `tap list`, `tap ask "..."`) and gets the outputs the README shows.
- Failure: someone edits `.claude/rules/skilltap.md` text in the product without updating `agent-prompt.md`, or types `tap ask --top 3` in the README; the docs test fails and names the block.

## Risks and open questions

- Example output shows section text from the fixture skills, not from a famous catalog; a real catalog example (Cloudflare skills) is more convincing but depends on a live download, so it is left out of the tested examples.
- The package name `skilltap` may change if it is taken on npm; R5 keeps the install text tied to `package.json`, but prose elsewhere says "SkillTap" and `tap`.
- The default Claude Code mode is not decided until C3; the README must present both modes neutrally and say the default is pending.
- Installing from the public GitHub repo (before an npm release) is a possible second install route; left out until the public repo has a `main` branch.

## Size and safety

About 600 lines of Markdown plus a docs test of about 150 lines; no runtime code changes. The test runs the CLI only against fixture skills in temporary directories and makes no network call. Merging cannot break the product; the worst case is wrong prose, which the tests are there to catch.
