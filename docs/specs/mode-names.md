# Spec: name the two Claude Code modes for what they do (`auto` and `ask`), and state the measured default

Status: APPROVED by user 2026-10-13 (the recommendation "rename the modes to `auto` and `ask`, keep `hook` and `pull` as aliases, rewrite the docs around the new names" was approved in chat). Slice 12 of the open-source release.
Spec-ID: mode-names
Scope: apps/cli/**, packages/claude/**, README.md, docs/guide/**

## Purpose

"Hook" and "pull" describe mechanisms, and "pull" collides with `git pull`. Name the modes after who starts the lookup, so a reader knows at once what each does: in **auto** mode SkillTap adds the matching sections to every prompt by itself; in **ask** mode Claude runs `tap ask` itself when a task may need a skill. Say in the README which mode is the default and why, using only what C3 measured.

## Non-goals

No change to what either mode does, to the hook protocol (`tap hook claude` stays, because it is the command Claude Code runs), to the init record format or file locations, to retrieval or delivery, and no new measurement. `hook` and `pull` stay accepted forever as aliases.

## Behaviour

`tap init claude --mode auto|ask` (aliases `hook`, `pull`; default `auto`, which is the old default `hook`). Messages, plans, the usage text, the header line of `.claude/rules/skilltap.md` and the documentation say `auto` and `ask`; the words "hook" and "pull" remain only where they name the Claude Code hook mechanism or the alias. The init record keeps writing `hook` and `pull` in its `mode` field, so existing projects, records and `--undo` keep working with no migration.

## Requirements

- R1 Names: `--mode auto` and `--mode ask` work exactly as `--mode hook` and `--mode pull` did; `--mode hook` and `--mode pull` still work and give identical results; any other value exits 2 with a message that lists `auto`, `ask` and the two aliases.
- R2 Default: with no `--mode`, the mode is `auto`; the plan and the summary say so by name.
- R3 Output: the usage text, the plan and summary lines of `tap init claude` and the rules-file header line name the modes `auto` and `ask`, never `hook mode` or `pull mode`; the rules-file body text is unchanged.
- R4 Compatibility: a project initialised with the old names (record `mode` of `hook` or `pull`) can be switched, re-run and undone with the new names, and the reverse, with identical files.
- R5 README: the Claude Code section explains the two modes in plain words in the first two sentences, using the table `who starts the lookup / what is always in context / risk`, states the default and the single reason for it (C3, amended), and avoids "pull" for the mode (the word is used only for `git pull` or the alias).
- R6 Measured statement: the README quotes the C3 result inside a `<!-- measured:c3 -->` region, with its limits: native loading skipped skills in a fifth to a third of runs, two catalogs, one model and one Claude Code build, the verdict was amended after the data was seen, ask mode was not shown to be cheaper on one catalog, and C3b is not run; the docs test allows figures only inside the measured regions and requires the limits sentence.
- R7 Guide: `docs/guide/claude-code.md` and `agent-prompt.md` use the new names throughout, and every `tap init claude --mode` example in the docs uses `auto` or `ask`.
- R8 Gates: `npm run check`, `npm test` and `npm run release:check` pass; the docs examples are regenerated by `UPDATE_DOCS=1`.

## Examples (single happy path and single failure, not a test plan)

- Happy path: `tap init claude ./skills --mode ask` writes the rules file whose first line says `--mode ask`; `tap init claude --mode auto` afterwards removes that file and installs the hook.
- Failure: `tap init claude --mode hook-ish` exits 2 with `--mode must be auto or ask (hook and pull are accepted as aliases)`.

## Size and safety

About 150 lines of code and tests plus documentation edits. No data format changes, no network, no new files outside the project. Worst case is a stale name in a message, which the tests grep for.
