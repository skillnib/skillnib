# Spec: rename the product to SkillNib (package `skillnib`, command `nib`)

Status: APPROVED by user 2026-10-14 (slice 14). The user chose the name on 2026-10-14 ("skillnib is great"); `skilltap` is used on npm by an unrelated project in the same space (skilltap.dev) and the `tap` command collides with the `tap` test runner's binary.
Spec-ID: rename-skillnib
Scope: package.json, README.md, apps/**, packages/*/src/**, packages/*/package.json, packages/*/tests/**, packages/*/node/**, tools/**, docs/guide/**, docs/process/**, .gitignore

## Purpose

Give the product a name that is free on npm and distinct in its space, before anything is published. After this change a user installs `skillnib`, runs `nib`, and sees no trace of the old names in the product, its output or its documentation.

## Non-goals

No behaviour change. No compatibility with the old names (nothing was published; the store directory and environment variable are not read under the old names). No edits to historical records: approved specs under `docs/specs/` (editing them would break their recorded links), `docs/research/`, `docs/roadmap.md`, `AGENTS.md` and the path `packages/catalog/skills/skilltap-delivery-framework/` that `AGENTS.md` names. The public repository moves to https://github.com/skillnib/skillnib (created by the user, empty) and its URLs change here; seeding it with `main` stays the release script's job and the user's action. No domain, logo or npm publishing.

## Names

| Was | Becomes |
| --- | --- |
| package `skilltap` | `skillnib` |
| command `tap` | `nib` (the only `bin` entry) |
| internal packages `@skilltap/*` | `@skillnib/*` |
| product name in prose "SkillTap" | "SkillNib" |
| store directory `.skilltap` | `.nib` |
| environment variable `SKILLTAP_STORE` | `NIB_STORE` |
| rules file `.claude/rules/skilltap.md` | `.claude/rules/nib.md` |
| public repository `skilltapsh/skilltap` | `skillnib/skillnib` (package.json, README links, release script default) |
| MCP `serverInfo.name` `skilltap` | `skillnib` |
| hook command `tap hook claude` | `nib hook claude` |

## Requirements

- R1 Package: `package.json` has the name `skillnib` and the single bin `nib` pointing at the same entry file; `nib --version` prints the version; the packed tarball is `skillnib-<version>.tgz`; the packed `package.json` has no `tap` bin.
- R2 Output: the usage text, error messages, plans, summaries, the fail-open notice, the delivery framing and every hint that names a command say `nib`, never `tap`; the fetch hint reads `nib show <ref>`; the pull-mode note and the rules-file header name `nib`.
- R3 Files and variables: the default store is `.nib` (nearest `.nib` above the working directory), the override variable is `NIB_STORE`, `nib init claude` writes `.claude/rules/nib.md` in ask mode and a hook command of the form `nib hook claude` (or the absolute `node "<path>" hook claude` form), and no code path reads or writes `.skilltap` or `SKILLTAP_STORE`.
- R4 MCP: the server reports the name `skillnib`; the guide's client configuration uses `"command": "nib"`.
- R5 Internal names: every `@skilltap/*` package name, comment and error string becomes `@skillnib/*`; the runtime-neutral markers and the package-boundary check keep working.
- R6 Documentation: the README and the guide pages use "SkillNib" and `nib` throughout; their example output is regenerated by the docs test and matches the real command; the install section names the package from `package.json` and `nib --version`.
- R7 No stale names: a test scans `package.json`, `README.md`, `apps/`, `packages/` (sources, tests, package files), `tools/`, `docs/guide/`, `docs/process/` and `.gitignore` and fails on any occurrence of `skilltap` (any case) or of the command `tap` outside a listed allowlist, which is empty (this spec is not scanned).
- R8 Gates and release: the approved specs' recorded links still verify unchanged; `npm run check`, `npm test` and `npm run release:check` pass; the release script and its tests use the new names; the C3 and C3b results records are untouched.
- R9 Tests: every existing test still runs under its original requirement tag; the count of tests does not go down.

## Examples (single happy path and single failure, not a test plan)

- Happy path: `npm install -g skillnib` then `nib import ./skills` and `nib ask "how should I word an error?"` print the same sections as `tap` did, with the fetch hint `nib show <ref>`.
- Failure: someone adds a message that says `run tap import first`; the stale-name test fails and names the file and line.

## Size and safety

A mechanical change touching about 80 files and about 600 lines, with no logic edits beyond string constants. The riskiest parts are strings that tests compare against real output (regenerated by the docs test) and file names built from the constants. Merging breaks nothing outside the repository because nothing was published.

## Risks and open questions

- The new repository `https://github.com/skillnib/skillnib` exists and is empty; the release script's default public URL changes to it, and the old `skilltapsh/skilltap` repository can be archived or deleted by the user.
- The `nib` command might collide with another tool on a user's machine; nothing known to install a `nib` binary was found.
- Historical documents mention SkillTap and `tap`; they are records of what was true then and are left as they are.
